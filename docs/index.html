Section 01 // Project Foundation

Executive Overview & Problem Formulation

Academic problem statement, higher-order vision, user personas, and comparative value proposition formulated for UCS503P at Thapar Institute of Engineering and Technology.

The Industry & Campus Pain Point Status Quo Deficiencies

Why Hackathon Team Formation Fails Today

Hackathons and multidisciplinary technical builds require diverse complementary skill sets (e.g., deep learning + mobile frontends + smart contracts) that a single college department rarely provides. Current student collaboration suffers from 4 fundamental bottlenecks:

  • Extreme Fragmentation: Teammate discovery is scattered across unsearchable WhatsApp chats, batch Discord servers, and informal personal networks.
  • Zero Cross-College Visibility: A Thapar ML engineer who needs a Flutter UI developer has zero mechanism to discover a talented developer at DTU or PEC searching for that exact project.
  • Trust & Verification Deficit: Open forums and social posts cannot verify actual student standing, leading to unresponsive teammates, ghosting, or falsified technical skills.
  • Poor Skill Complementarity: Keyword matching pairs people with identical stacks (two Python backend devs) rather than complementary pairs (Frontend + Backend).
The TeamSync Solution Engineering Proposition

Structured, Verifiable, Complementary Matching

TeamSync translates skill-based teammate discovery into a deployable, 3-tier web platform tailored specifically to time-boxed hackathon sprints:

  • College Email Verification: Sign-ups are strictly gated behind verified institutional domains (`@thapar.edu`), guaranteeing student authenticity.
  • GitHub Proof of Work: Integrated GitHub API signals display verified commit frequency, top languages, and active repositories.
  • Heuristic Scoring Engine: Ranks candidates via complementary skill overlap, domain interest alignment, and availability window without black-box opacity.
  • Integrated Team Workspace: In-app connection handshake, encrypted coordination chat, and Kanban task allocation for the duration of the hackathon.

Section 06 // Core Innovation

The Heuristic Matching Engine & Live Simulator

Transparent weighted-overlap formulation designed for academic explainability, zero cold-start barriers, and real-time candidate ranking.

Mathematical Formulation

Rather than deploying a high-opacity neural recommender requiring thousands of interaction records, TeamSync computes a composite heuristic score \(S(u, L) \in [0, 1]\) evaluating candidate student \(u\) against project listing \(L\):

\[S(u, L) = w_1 \cdot C_{\text{skills}}(u, L) + w_2 \cdot O_{\text{domain}}(u, L) + w_3 \cdot G_{\text{github}}(u) + w_4 \cdot A_{\text{avail}}(u)\]
Subject to constraint: \(w_1 + w_2 + w_3 + w_4 = 1.0 \quad (w_1=0.45, \; w_2=0.25, \; w_3=0.15, \; w_4=0.15)\)
\(C_{\text{skills}}(u, L)\) Jaccard overlap between candidate's verified skills and listing's required tech stack tags.
\(O_{\text{domain}}(u, L)\) Cosine similarity of interest vectors (e.g., Fintech, Healthcare, EdTech, Web3).
\(G_{\text{github}}(u)\) Verified activity index computed from repository commits and language badges.
\(A_{\text{avail}}(u)\) Commitment coefficient (e.g., 24h, 36h, 48h active weekend sprint availability).

Section 08 // Risk Engineering

Risk Assessment & Mitigation Matrix

Structured risk analysis identifying critical operational, technical, and behavioural failure modes with pre-emptive mitigation plans.

Risk ID Risk Description Likelihood Impact Pre-Emptive Mitigation Strategy Contingency Plan
RSK-01 Cold-Start Deficit (Few initial listings) Medium High Schedule pilot launch strictly in sync with an active scheduled college hackathon (e.g., TIET Hack-O-Week) to pool natural demand. Pre-seed mock listings based on real student teams seeking partners.
RSK-02 Identity & Student Spoofing Low High Enforce programmatic regex validation permitting only approved college domain suffixes (`@thapar.edu`). Immediate token revocation on domain mismatch or spam report.
RSK-03 Cross-College Communication Friction Medium Medium Provide built-in in-app real-time messaging with browser notifications so users do not depend on external social handles. Fallback email notifications dispatched on pending connection requests.
RSK-04 Heuristic Weight Inaccuracy Medium Low Implement configurable coefficient weights (\(w_1\) to \(w_4\)) tunable dynamically without modifying core algorithms. Allow users to manually adjust preference weights directly in search view.
RSK-05 Pilot UAT Survey Abandonment Medium Low Replace lengthy surveys with a simple single-click 1-to-5 star clarity question immediately after match acceptance. Conduct short 3-minute qualitative interviews with 5 active pilot leaders.

Local Deployment Guide 

# Clone repository
git clone https://github.com/AaditaGarg/TeamSync.git
cd TeamSync/code

# Install React 19 dependencies
npm install

# Start local development server
npm run dev
# -> Opens http://localhost:5173
